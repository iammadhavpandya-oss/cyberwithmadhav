3.11.01

NTP: why every device needs the right time

When something goes wrong at 02:14 on the firewall, you want to line it up with what the core switch logged at 02:14. If one device is seven minutes fast, that timeline is useless. Wrong time also breaks certificate checks (a certificate can look "not yet valid") and some authentication.

  • NTP uses UDP port 123 and is organised by stratum: stratum 1 servers are directly attached to a reference clock (GPS, atomic), stratum 2 learn from stratum 1, and so on. Stratum 16 means unsynchronised.
  • ntp server 192.168.1.100 makes a Cisco device an NTP client of that server. Its own stratum becomes the server's plus one.
  • A device can also serve time to others; on IOS, ntp master makes a router an authoritative source when nothing better exists.
  • service timestamps log datetime msec puts the date and time, to the millisecond, on every log message.
R1(config)#ntp server 192.168.1.100
R1(config)#service timestamps log datetime msec
R1#show ntp status
Clock is synchronized, stratum 2, reference is 192.168.1.100
R1#show ntp associations
R1#show clock detail
Hinglish mein samjho

Sabhi devices ka time same hona chahiye, warna logs ki timeline bekaar aur certificates fail. NTP UDP 123, stratum se chalta hai: stratum 1 reference clock ke paas, 16 matlab unsynchronised. ntp server se device client banta hai, uska stratum server se ek zyada. service timestamps log datetime msec se har log pe exact time.

3.11.02

Syslog and severity levels

Cisco messages look like %LINK-3-UPDOWN: Interface GigabitEthernet0/0/1, changed state to down: facility (LINK), severity (3), mnemonic (UPDOWN), then the text. Syslog sends them to a server over UDP port 514.

Syslog severity levels
LevelKeywordMeaning
0emergenciesSystem unusable
1alertsImmediate action needed
2criticalCritical condition
3errorsError condition, for example %LINK-3-UPDOWN
4warningsWarning
5notificationsNormal but significant, for example %SYS-5-CONFIG_I
6informationalInformational
7debuggingDebug output, the least severe

Choosing a level means "this level and everything more severe". logging trap informational (6) sends levels 0 to 6 and skips debugging. A common trap: thinking 7 is the most serious. It is the least.

R1(config)#logging host 192.168.1.100
R1(config)#logging trap informational
! older IOS form: logging 192.168.1.100
R1#show logging
How attackers abuse this

An intruder who gets onto a router can clear its local log buffer, and with it the evidence of what they did. If time is wrong or logs stay on the box, the investigation has nothing to work with.

Defender move

Send logs off the device to a syslog server or SIEM the network team cannot quietly edit, keep NTP correct everywhere, and alert on config change messages such as %SYS-5-CONFIG_I outside change windows. Restrict NTP to known servers, using NTP authentication and ACLs where you can.

Hinglish mein samjho

Message format: %FACILITY-SEVERITY-MNEMONIC. Syslog UDP 514. Levels 0 (emergencies) se 7 (debugging); 0 sabse serious, 7 sabse kam. logging trap informational matlab 0 se 6 tak sab. Attacker local logs clear kar sakta hai, isliye logs server ya SIEM pe bhejo aur config change alerts lagao.

3.11.03

SNMP: monitoring devices

A network management system (NMS, the manager) polls agents on devices with SNMP over UDP port 161, and agents send traps or informs (an inform is a trap that expects an acknowledgement) to UDP port 162 when something happens. The data is organised in a MIB (management information base); each value, such as sysUpTime or an interface counter, has an OID (object identifier).

SNMP versions
VersionSecurityUse
SNMPv1, v2cA community string, sent in cleartext. RO lets you read, RW lets you change settings.Labs, or read only behind strict ACLs
SNMPv3Users with authentication and optional encryption (noAuthNoPriv, authNoPriv, authPriv)Production: use authPriv
R1(config)#access-list 20 permit host 192.168.1.50
R1(config)#snmp-server community CwmLabRO ro 20
! SNMPv3 outline (concept, see lab notes):
R1(config)#snmp-server group OPS v3 priv
R1(config)#snmp-server user nms1 OPS v3 auth sha AUTHPASS priv aes 128 PRIVPASS

Communities named public and private are the first thing scanners try. A read-write v2c community is effectively a cleartext admin password. Never configure one on a production device.

Hinglish mein samjho

NMS agents ko UDP 161 pe poll karta hai, agents events pe UDP 162 pe trap bhejte hain. MIB data model hai, OID ek value. v1/v2c mein community string cleartext jaati hai; RW community matlab cleartext admin password. Production mein SNMPv3 authPriv aur ACL.

3.11.04

QoS in one picture

  • Classification and marking: identify traffic and mark it so later devices do not have to look again. At Layer 3, the DSCP field in the IP header (voice is usually EF, value 46). At Layer 2, the 3 bit CoS field in the 802.1Q tag.
  • Trust boundary: the point where you start believing markings. Usually the access switch port toward an IP phone, never a user PC that could mark its own downloads as voice.
  • Queuing: a strict priority queue for voice (small, delay sensitive), weighted queues for the rest.
  • Congestion avoidance: WRED drops some TCP packets early, so senders slow down before the queue overflows.
  • Policing vs shaping: a policer drops or re-marks traffic above a rate; a shaper buffers and delays it. Service providers police; customers shape to stay under the contract rate.

Voice and video care about delay, jitter (variation in delay) and loss. Commonly quoted targets for voice are one way delay under about 150 ms, jitter under about 30 ms and loss under 1 percent.

Hinglish mein samjho

QoS bandwidth nahi badhata, congestion mein decide karta hai kaun wait kare. Classify aur mark (DSCP, voice EF 46; CoS 802.1Q tag mein), trust boundary phone wale port pe, voice ke liye priority queue, WRED early drop, policing drop karta hai aur shaping delay. Voice ko delay, jitter aur loss pareshan karte hain.

3.11.05

Backups: TFTP, FTP and the secure options

File transfer options
ProtocolTransportAuthenticationEncryption
TFTPUDP 69NoneNone
FTPTCP 21 control, 20 data (active mode)Username and passwordNone, credentials in cleartext
SCP, SFTPTCP 22 (SSH)SSH credentials or keysYes
R1#copy running-config tftp:
Address or name of remote host []? 192.168.1.100
Destination filename [r1-confg]?
!!
R1#copy tftp: running-config      ! restore (merges into the running config)

TFTP is fine on an isolated lab network and nowhere else: anyone on the path can read the file, and anyone who can reach the server can overwrite it. Your configuration contains password hashes, SNMP communities and keys, so treat backups like secrets.

Hinglish mein samjho

TFTP UDP 69, na authentication na encryption, sirf isolated lab ke liye. FTP mein password cleartext. Production mein SCP ya SFTP. copy running-config tftp: se backup. Config mein hashes, communities aur keys hote hain, backup ko secret ki tarah rakho.

    Hands-on lab

    Cisco Packet Tracer lab45 minutessimulated network

    Packet Tracer lab 3.11: time, logs, SNMP and backups

    You need: Cisco Packet Tracer (free with a Cisco Networking Academy account; version 9.0.1 was the current download on the NetAcad Resource Hub when this lesson was written). Devices: 1 x ISR4331, 1 x 2960, 1 x Server-PT (Server-Ops), 1 x PC-PT (NMS-PC).

    Simulator lab, zero risk. This lab runs inside Cisco Packet Tracer, so it touches no real network. Packet Tracer is free with a Cisco Networking Academy account (netacad.com). It simulates a subset of Cisco IOS, so where support for a feature is uncertain we say so instead of promising it works.

    Topology and addressing

    Addressing table
    DeviceInterfaceIPv4 address / prefixDefault gateway or note
    R1Gi0/0/0192.168.1.1/24
    SW1VLAN 1192.168.1.2/24default gateway 192.168.1.1
    Server-OpsFa0192.168.1.100/24NTP, syslog, TFTP, FTP

    1. Server services

      On Server-Ops, open Services and turn on NTP, Syslog, TFTP and FTP. Add an FTP user with write permission.

    2. NTP on R1 and SW1

      ntp server 192.168.1.100
service timestamps log datetime msec

      Sync can take a minute or more of simulated time; use the fast forward button.

    3. Syslog on R1 and SW1

      logging host 192.168.1.100
logging trap informational

      If logging host is rejected, try the older form logging 192.168.1.100.

    4. Make some logs

      Shut and unshut an interface, enter and leave configuration mode, then open Services, Syslog on Server-Ops and find the entries from 192.168.1.1 and 192.168.1.2.

    5. SNMP on R1 (v2c, lab only)

      R1(config)#access-list 20 permit host 192.168.1.50
R1(config)#snmp-server community CwmLabRO ro 20

      On NMS-PC open Desktop, MIB Browser: target 192.168.1.1, community CwmLabRO, then GET sysName or sysUpTime.

    6. Back up the config

      R1#copy running-config tftp:
Address or name of remote host []? 192.168.1.100
Destination filename [r1-confg]?

      Check the TFTP file list on Server-Ops. Optionally try ip ftp username, ip ftp password and copy running-config ftp:.

    7. Verify

      R1#show ntp status
R1#show ntp associations
R1#show clock detail
R1#show logging

    You are done when: show ntp status says synchronised with reference 192.168.1.100, show clock detail names NTP as the source, show logging shows trap level informational and host 192.168.1.100, Server-Ops lists syslog entries from both devices, the MIB Browser GET returns a value, and r1-confg appears in the TFTP list.

    Packet Tracer limits and notes

    • SNMPv3 commands (snmp-server group, snmp-server user ... auth sha ... priv aes) in Packet Tracer are UNVERIFIED. If rejected, treat SNMPv3 as concept.
    • ntp master and NTP authentication on Packet Tracer routers are UNVERIFIED. The Server-PT NTP service is the dependable time source.
    • Whether logging host, logging <ip> or both are accepted depends on the image: UNVERIFIED.
    • QoS configuration (class-map, policy-map, service-policy) support in Packet Tracer is partial and UNVERIFIED, so QoS stays conceptual here.
    • FTP copy from IOS in Packet Tracer is UNVERIFIED; TFTP copy works in the outline author's experience. show snmp community is also UNVERIFIED.
    • Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.

    Key takeaways

    • Correct time everywhere, from NTP, makes logs and certificates trustworthy.
    • Severity 0 is the worst and 7 the least; a trap level includes everything more severe.
    • Send logs off the box and alert on config changes.
    • SNMP v2c communities are cleartext; use v3 authPriv and ACLs.
    • QoS manages congestion; it does not add bandwidth.
    • Back up configs over SCP or SFTP and protect the files.
