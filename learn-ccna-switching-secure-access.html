3.3.01

How a switch learns, forwards, floods and filters

  • Learn: the switch records the source MAC of every incoming frame against the port it arrived on.
  • Forward: a known destination MAC goes out only its port. Filter: if the destination is on the same port it came in on, the frame is dropped.
  • Flood: unknown unicast, broadcast (ff:ff:ff:ff:ff:ff, for example ARP requests) and, by default, multicast go out every port in the VLAN except the one they came in on.
  • Age: entries that are not refreshed expire, after 300 seconds by default on Catalyst switches. Many MACs can sit behind one port, for example everything learned through an uplink to another switch.
How attackers abuse this

MAC flooding (CAM table overflow): a tool sends thousands of frames with random fake source MACs until the table is full. The switch can no longer learn real addresses, floods traffic like a hub, and the attacker's port now sees other people's frames.

Defender move

Port security limits how many MACs a port may learn and shuts or restricts the port when the limit is hit (lesson 3.12). Watch logs for MAC flapping, where the same MAC jumps between ports.

Hinglish mein samjho

Switch source MAC se seekhta hai (kaunsa MAC kis port pe), destination MAC se forward karta hai. Unknown ya broadcast frame sab ports pe flood hota hai. Entries 300 second baad expire. MAC flooding attack table bhar deta hai aur switch hub jaisa flood karne lagta hai; port security isko rokta hai.

3.3.02

Managing a switch: SVI, gateway and access methods

A Layer 2 switch does not need an IP address to switch frames. It needs one only so you can manage it remotely. That address lives on a virtual interface, the SVI (switch virtual interface), such as interface vlan 1 or better, a dedicated management VLAN. Because a pure Layer 2 switch does not route, it also needs ip default-gateway to answer admins on other subnets.

SW1(config)#interface vlan 1
SW1(config-if)#ip address 192.168.1.2 255.255.255.0
SW1(config-if)#no shutdown
SW1(config-if)#exit
SW1(config)#ip default-gateway 192.168.1.1

Defender move

Keep management on its own VLAN and subnet, reachable only from admin machines, and restrict the VTY lines with an access list (access-class, lesson 3.9). Many attacks on network gear start with a management interface that was reachable from everywhere.

Hinglish mein samjho

Switch ko frames switch karne ke liye IP nahi chahiye; IP sirf management ke liye SVI (interface vlan) pe lagta hai, saath mein ip default-gateway. Telnet cleartext hai, SSH use karo. Web UI use nahi karte toh band karo. Management alag VLAN pe rakho aur access-class se VTY restrict karo.

3.3.03

Passwords on Cisco devices: what each type really means

Cisco password types
In the configWhat it isVerdict
enable password cisco (type 0)Plain textNever use
password 7 0822455D0A16 (type 7)Scrambled with a public algorithm, made by service password-encryptionReversible in a second: hides from shoulder surfers only
secret 5 $1$... (type 5)MD5 based hashBetter, but old and fast to crack
secret 8 / secret 9PBKDF2-SHA256 / scrypt hashes on newer IOSBest where your IOS supports them

So: always use enable secret (never enable password), create users with username NAME secret PASSWORD, and still turn on service password-encryption so any remaining line passwords are at least not readable over someone's shoulder. On real IOS 15.3 and later you can choose the strongest hash with enable algorithm-type scrypt secret ...; Packet Tracer support for that is UNVERIFIED.

Type 7 decoder: see why it is not encryption

Paste a type 7 string from a config (the part after password 7). The algorithm and its key are public, so anyone can reverse it. Only paste lab strings, never a real device's.

Plain text:

How attackers abuse this

Config files get shared in tickets, emailed to vendors and posted on forums for help. Any type 7 password in them can be decoded instantly, as the widget shows, and weak type 5 hashes can be cracked offline.

Defender move

Treat a config file as a secret. Strip passwords before sharing, prefer AAA with central accounts and MFA (lesson 3.12), and choose long passphrases over short complex ones: length beats complexity rules, never reuse, and use MFA, certificates or biometrics where possible.

Hinglish mein samjho

enable password ya type 0 plain text hai. Type 7 (service password-encryption) public algorithm hai, ek second mein decode ho jaata hai, widget mein dekho. Type 5 MD5 hash, type 8/9 behtar. Hamesha enable secret aur username ... secret use karo. Config file ko secret samjho, share karne se pehle passwords hatao.

3.3.04

SSH only: the full recipe

Typing ip ssh version 2 alone does nothing useful. SSH needs all of these, in this order:

  1. A hostname that is not the default (hostname SW1) and a domain name (ip domain-name cyberwithmadhav.lab), because the RSA key is named after both.
  2. An RSA key pair: crypto key generate rsa, then answer the modulus question. Version 2 needs at least 768 bits; 2048 is a sensible modern choice.
  3. ip ssh version 2.
  4. A local user: username netadmin secret ....
  5. VTY lines that use it and refuse Telnet: line vty 0 15, login local, transport input ssh.

Do the whole baseline in the simulator. Passwords here are lab examples; never reuse them anywhere real.

    3.3.05

    CDP and LLDP: useful maps, useful to attackers too

    CDP (Cisco Discovery Protocol) is Cisco proprietary and on by default on Cisco gear. Every 60 seconds each device tells its neighbours its name, model, IOS version, port and management address. LLDP (IEEE 802.1AB) does the same across vendors and is usually off on Cisco IOS until you type lldp run.

    SW1#show cdp neighbors
Device ID        Local Intrfce   Holdtme    Capability   Platform    Port ID
SW2              Gig 0/1         150        S I          2960        Gig 0/1
R1               Fas 0/24        140        R B S I      ISR4331     Gig 0/0/0
SW1#show cdp neighbors detail
SW1(config)#lldp run
SW1#show lldp neighbors
    How attackers abuse this

    Anyone plugged into a user port receives these advertisements: the switch model, its exact IOS version (handy for finding known vulnerabilities), management IPs and VLAN details. Reconnaissance for free.

    Defender move

    Keep CDP or LLDP on infrastructure links where they help you, and turn them off on user facing ports: no cdp enable per interface (or no cdp run globally) and no lldp transmit plus no lldp receive.

    Hinglish mein samjho

    CDP (Cisco, default on) aur LLDP (multi-vendor, Cisco pe default off) neighbours ko naam, model, IOS version, port aur IP batate hain. Admin ke liye map, attacker ke liye free recon. User ports pe band karo (no cdp enable, no lldp transmit/receive), infrastructure links pe rakho.

    Packet Tracer limits and notes

    • Some Packet Tracer images accept only line vty 0 15 on switches and line vty 0 4 on some routers. Use what the device accepts. UNVERIFIED for every model.
    • An RSA modulus of 2048 is accepted by recent Packet Tracer versions in common lab guides, but this is UNVERIFIED for every image. If rejected, use the largest value offered (at least 1024).
    • LLDP on Packet Tracer's 2960 and ISR models: UNVERIFIED for every build. login block-for exists in IOS; Packet Tracer support UNVERIFIED.
    • enable algorithm-type scrypt secret (type 9) is real IOS; Packet Tracer support UNVERIFIED.

    Key takeaways

    • Switches learn from source MACs and flood the unknown.
    • Management needs an SVI and, on a Layer 2 switch, a default gateway.
    • enable secret and username secret; type 7 is not encryption.
    • SSH needs hostname, domain, keys, a user and transport input ssh.
    • CDP and LLDP belong on infrastructure links, not user ports.
