3.9.01

How an ACL decides

An access control list is an ordered list of permit and deny lines. When a packet is checked against it, the router:

  1. Compares the packet with the first line, then the next, top to bottom.
  2. Stops at the first line that matches and does what it says. Later lines are never read for that packet.
  3. If no line matches, drops the packet. Every ACL ends with an invisible deny any.

That last rule causes the classic outage: an ACL with only deny host 192.168.10.10 does block that host, and it also blocks everyone else, because nothing is permitted. If you mean "everyone except this host", add permit any at the end.

Standard and extended ACLs
TypeNumbersMatches onPlace it
Standard1 to 99, 1300 to 1999Source IP onlyClose to the destination, so it does not block the source from everywhere else.
Extended100 to 199, 2000 to 2699Protocol, source, destination, ports, some flagsClose to the source, so unwanted traffic is dropped before it crosses the network.

On an interface you get one ACL per direction per protocol: one IPv4 ACL in, one out. "In" means packets arriving on that interface, before routing. "Out" means packets leaving it, after routing. Outbound ACLs do not filter packets the router itself generates, such as its own pings or routing updates.

Hinglish mein samjho

ACL upar se neeche check hota hai, pehli matching line decide karti hai, aur end mein invisible deny any hota hai. Sirf deny wali ACL sabko block kar deti hai, isliye permit any lagana padta hai. Standard (1-99, 1300-1999) sirf source dekhta hai, destination ke paas lagao. Extended (100-199, 2000-2699) protocol, source, destination aur ports dekhta hai, source ke paas lagao. Interface pe ek direction mein ek hi IPv4 ACL.

3.9.02

Wildcard masks

ACLs (and OSPF network statements) use wildcard masks: a 0 bit means "this bit must match", a 1 bit means "ignore this bit". For a normal subnet the wildcard is the subnet mask inverted, which you can get by subtracting each octet from 255.

Wildcard examples
To matchAddress and wildcardShortcut
One host192.168.10.10 0.0.0.0host 192.168.10.10
A /24192.168.20.0 0.0.0.255
A /26 (64 addresses)192.168.20.64 0.0.0.63
A /3010.0.13.0 0.0.0.3
All of 192.168.0.0 to 192.168.255.255192.168.0.0 0.0.255.255
Everything0.0.0.0 255.255.255.255any

Wildcards can also match patterns a subnet mask cannot. 192.168.1.0 0.0.254.255 matches every odd third octet (192.168.1.x, 192.168.3.x and so on). You will rarely write one, but you should recognise that a wildcard is not always a contiguous block.

Hinglish mein samjho

Wildcard mein 0 matlab match karna zaroori, 1 matlab ignore. Normal subnet ke liye 255 mein se mask ka har octet ghatao: /24 ka 0.0.0.255, /26 ka 0.0.0.63, /30 ka 0.0.0.3. host = 0.0.0.0, any = 255.255.255.255.

3.9.03

Numbered, named and extended syntax

! numbered standard
R1(config)#access-list 10 deny host 192.168.10.10
R1(config)#access-list 10 permit any
! named extended, with sequence numbers
R1(config)#ip access-list extended GUEST-IN
R1(config-ext-nacl)#10 permit udp 192.168.20.0 0.0.0.255 host 10.10.10.10 eq domain
R1(config-ext-nacl)#20 permit tcp 192.168.20.0 0.0.0.255 host 10.10.10.10 eq www
R1(config-ext-nacl)#30 deny ip 192.168.20.0 0.0.0.255 192.168.0.0 0.0.255.255 log
R1(config-ext-nacl)#40 permit ip 192.168.20.0 0.0.0.255 any
! insert or delete one line later
R1(config-ext-nacl)#15 permit icmp 192.168.20.0 0.0.0.255 host 10.10.10.10 echo
R1(config-ext-nacl)#no 30
! apply
R1(config)#interface GigabitEthernet0/0/0.20
R1(config-subif)#ip access-group GUEST-IN in
  • Extended line order: action protocol source [source port] destination [destination port] [options]. Ports need tcp or udp.
  • Port operators: eq, neq, gt, lt, range. Names like www (80) and domain (53) are accepted.
  • established matches TCP packets with ACK or RST set, which is a cheap way to allow replies. It is a flag check, not session tracking, so it is not a stateful firewall.
  • Named ACLs give each line a sequence number, so you can insert line 15 between 10 and 20 or delete one line, instead of deleting and retyping a numbered list.
Hinglish mein samjho

Extended order: action, protocol, source, source port, destination, destination port. Ports ke liye tcp ya udp chahiye. eq, neq, gt, lt, range. established sirf ACK/RST flag check hai, stateful firewall nahi. Named ACL mein sequence numbers se beech mein line daal sakte ho ya ek line hata sakte ho.

    3.9.05

    Protecting the router itself

    An ACL on a data interface does not protect SSH to the router from every direction. For the VTY lines use access-class, which filters who may open a remote session, whichever interface they arrive on.

    R1(config)#ip access-list standard MGMT-ONLY
R1(config-std-nacl)#permit 192.168.99.0 0.0.0.255
R1(config-std-nacl)#deny any log
R1(config)#line vty 0 4
R1(config-line)#access-class MGMT-ONLY in
    How attackers abuse this

    Once one guest laptop is compromised, a flat network lets the attacker scan and reach everything: staff PCs, printers, and the SSH prompt of every router and switch, where password guessing starts. The same goes for spoofed traffic arriving from the internet claiming to come from your own private ranges.

    Defender move

    Extended ACLs between VLANs so guests reach only what they need, access-class on every device's VTY lines so only the admin subnet can even try to log in, log on the important deny lines (sent to syslog in lesson 3.11), and edge filters that drop inbound packets with RFC 1918 or your own internal source addresses (the idea behind BCP 38).

    Hinglish mein samjho

    Router ke SSH ko bachane ke liye line vty pe access-class lagao, sirf admin subnet allowed. Attack: ek guest laptop compromise hua toh flat network mein sab reachable. Defence: VLANs ke beech extended ACLs, VTY pe access-class, deny lines pe log, aur internet se aane wale private source addresses drop karo.

      Quick quiz

      Instant feedback on every answer. Score 70% or more to pass this lesson's quiz.

      Q1An ACL contains only access-list 5 deny host 10.1.1.5 and is applied. What happens to traffic from 10.1.1.6?

      Nothing permits it, so the invisible deny any drops it.

      Q2Which wildcard matches 172.16.8.0/22?

      A /22 has 1024 addresses: 4 in the third octet, so 0.0.3.255.

      Q3Where should an extended ACL that blocks guests from staff be placed?

      Close to the source, so the traffic is dropped as early as possible.

      Q4How do you stop non-admins reaching SSH on a router?

      access-class filters sessions to the VTYs whatever interface they arrive on.

      Q5permit tcp any host 10.1.1.1 eq 22 established matches:

      established is a flag check for replies, not session tracking.

      Q6How many IPv4 ACLs can be applied inbound on one interface?

      One per interface, per direction, per protocol.

      3. Insert a line without retyping

        R1(config)#ip access-list extended GUEST-IN
R1(config-ext-nacl)#15 permit icmp 192.168.20.0 0.0.0.255 host 10.10.10.10 echo

      4. Standard ACL near the destination

        R1(config)#access-list 10 deny host 192.168.10.10
R1(config)#access-list 10 permit any
R1(config)#interface GigabitEthernet0/0/1
R1(config-if)#ip access-group 10 out

      5. Test from each PC

        From PC-Guest: browse http://10.10.10.10 (works), ping 10.10.10.10 (works after step 3), ping 192.168.10.10 (fails), SSH to 192.168.99.1 (fails). From PC-Staff: browse the server (fails after step 4). From Admin-PC: SSH to R1 (works).

      6. Verify

        R1#show access-lists
R1#show ip interface GigabitEthernet0/0/0.20
R1#show running-config | section vty

      You are done when: show access-lists shows every line with a sequence number and match counters that rise only on the lines your tests hit. show ip interface for Gi0/0/0.20 reports GUEST-IN as the inbound list. The VTY section shows access-class MGMT-ONLY in. PC-Staff cannot reach the server but PC-Guest can, because ACL 10 filters by source only.

      Packet Tracer limits and notes

      • Numbered and named standard and extended ACLs, sequence numbers and access-class work in Packet Tracer in the outline author's experience, but test in your own build.
      • The log keyword is accepted, but whether Packet Tracer actually generates log messages for ACL hits is UNVERIFIED. Rely on the match counters.
      • IPv6 ACLs (ipv6 access-list with ipv6 traffic-filter) follow the same ideas but are not part of this lab.
      • Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.

      Key takeaways

      • First match wins, and every ACL ends with an invisible deny any.
      • Standard near the destination, extended near the source.
      • Wildcard = 255 minus each mask octet for normal subnets.
      • Use named ACLs so you can insert and delete single lines.
      • Protect the management plane with access-class, and log the denies that matter.
