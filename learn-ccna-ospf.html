3.8.01

Link state routing in plain words

Static routes from lesson 3.7 work until a link fails and nobody updates them. A dynamic routing protocol lets routers tell each other what they can reach and recalculate when something changes. OSPF (Open Shortest Path First) is the open standard one you will meet everywhere, and OSPFv2 carries IPv4.

  1. Each router finds neighbours by sending hello packets out of its OSPF interfaces (to multicast 224.0.0.5).
  2. Neighbours exchange LSAs (link state advertisements): descriptions of each router's links, subnets and costs.
  3. Every router in an area ends up with an identical link state database (LSDB), a map of the area.
  4. Each router runs the SPF (Dijkstra) algorithm on that map, with itself as the root, and installs the lowest cost paths in its routing table as O routes with administrative distance 110.
Think of it like this

Distance vector protocols work like asking for directions: each neighbour only tells you how far a place is. OSPF gives every router the same complete city map, and each one plans its own shortest route on it.

This lesson covers single area OSPF: everything is in area 0, the backbone. Multi area design exists for large networks and is beyond CCNA depth.

Hinglish mein samjho

Static routes link fail hone pe khud update nahi hote. OSPF mein routers hello bhej ke neighbours dhoondhte hain, LSAs exchange karte hain, sabke paas area ka same map (LSDB) hota hai, aur har router Dijkstra (SPF) chala ke apna shortest path nikaalta hai. Routing table mein yeh O routes hain, AD 110.

3.8.02

Becoming neighbours: states, timers and the must-match list

Hellos go out every 10 seconds on Ethernet, and a neighbour is declared dead after 40 seconds of silence (the dead interval). Two routers only become neighbours when these match:

OSPF neighbour requirements
Must matchWhat happens if it does not
Area IDNo adjacency. The hello is ignored.
Subnet and mask on the linkNo adjacency on broadcast links.
Hello and dead intervalsNo adjacency. Changing one side drops an existing neighbour when the dead timer runs out.
Authentication settingsNo adjacency.
Stub area flagNo adjacency (not used in this lesson).
MTUNeighbours get stuck in ExStart or Exchange.

What does not need to match: the process ID in router ospf 1. It is local to the router. Router IDs must be unique.

Router ID (a 32 bit name written like an IPv4 address) is chosen in this order: the router-id command; else the highest IP on a loopback interface that is up; else the highest IP on an active physical interface. A router ID only changes when the process restarts, so after changing it you run clear ip ospf process.

Hinglish mein samjho

Hello har 10 second, dead interval 40 second. Neighbour banne ke liye area, subnet, hello/dead timers, authentication aur stub flag match hone chahiye; MTU mismatch pe ExStart/Exchange mein atak jaate hain. Process ID local hai, match nahi karna. Router ID: router-id command, warna highest loopback IP, warna highest active interface IP. Change ke baad clear ip ospf process.

3.8.03

DR and BDR on shared LANs, and why point to point skips it

If ten routers share one Ethernet segment and every pair formed a full adjacency, that would be 45 adjacencies flooding the same updates. OSPF instead elects a designated router (DR) and a backup (BDR). Everyone forms a Full adjacency with the DR and BDR; the others (DROTHERs) stay at 2-Way with each other.

  • Highest OSPF interface priority wins (default 1, range 0 to 255). Priority 0 means "never be DR or BDR".
  • On a tie, the highest router ID wins.
  • The election is not preemptive. A router that joins later with a higher priority does not take over. The DR changes only if it fails (then the BDR is promoted) or the OSPF processes are restarted.

A link with only two routers (a /30 between R1 and R3, say) gains nothing from an election. ip ospf network point-to-point on both ends removes the DR/BDR step and the wait that comes with it, so the adjacency forms faster. Both ends must use the same network type.

DR related commands
CommandWhereEffect
ip ospf priority 200InterfaceMakes this router the likely DR on that segment (at the next election).
ip ospf priority 0InterfaceNever DR or BDR on that segment.
ip ospf network point-to-pointInterface, both endsNo DR/BDR election; neighbour shows FULL/ -.
Hinglish mein samjho

Shared LAN pe har pair ka adjacency banana waste hai, isliye DR aur BDR elect hote hain. Highest priority (default 1, 0 matlab kabhi nahi), tie pe highest router ID. Election preemptive nahi hai: baad mein aaya better router DR nahi chheenta, jab tak DR fail na ho ya process clear na karo. Do router wale link pe ip ospf network point-to-point lagao, election skip.

3.8.04

Configuring single area OSPF

R1(config)#interface Loopback0
R1(config-if)#ip address 1.1.1.1 255.255.255.255
R1(config-if)#exit
R1(config)#router ospf 1
R1(config-router)#router-id 1.1.1.1
R1(config-router)#network 172.16.100.0 0.0.0.255 area 0
R1(config-router)#network 10.0.13.0 0.0.0.3 area 0
R1(config-router)#network 192.168.1.0 0.0.0.255 area 0
R1(config-router)#network 1.1.1.1 0.0.0.0 area 0
R1(config-router)#passive-interface GigabitEthernet0/0/1
R1(config-router)#auto-cost reference-bandwidth 10000
! alternative to network statements, per interface:
R1(config)#interface GigabitEthernet0/0/1
R1(config-if)#ip ospf 1 area 0
  • A network statement does not advertise a prefix by itself. It says "run OSPF on every interface whose IP falls in this range", and those interfaces' subnets get advertised. It uses a wildcard mask: 0.0.0.255 for a /24, 0.0.0.3 for a /30, 0.0.0.0 for exactly one address.
  • passive-interface stops hellos on a LAN port but still advertises its subnet. Every user facing interface should be passive. passive-interface default followed by no passive-interface on router links is the safer habit.
  • default-information originate shares this router's default route with the rest of the area. Others see it as O*E2 0.0.0.0/0.
Hinglish mein samjho

network command wildcard mask ke saath batata hai ki kin interfaces pe OSPF chalana hai: /24 ke liye 0.0.0.255, /30 ke liye 0.0.0.3. Ya interface pe ip ospf 1 area 0. LAN ports passive karo: hello band, subnet phir bhi advertise. default-information originate se default route baaki routers ko milta hai (O*E2).

3.8.05

Cost: how OSPF picks the best path

OSPF's metric is cost, added up along the path. Interface cost = reference bandwidth / interface bandwidth, with a minimum of 1. The default reference is 100 Mb/s, which means FastEthernet, Gigabit and 10 Gigabit links all cost 1 and OSPF cannot tell them apart.

Interface cost by reference bandwidth
LinkCost, reference 100 (default)Cost, reference 10000
100 Mb/s1100
1 Gb/s110
10 Gb/s11

Fix it with auto-cost reference-bandwidth 10000 (in Mb/s) on every router, or set a link's cost directly with ip ospf cost N. In the routing table, [110/20] means AD 110 and total cost 20. If two paths have the same cost, OSPF installs both (up to 4 by default on IOS) and shares the load.

How attackers abuse this

A laptop on a user VLAN running routing software can speak OSPF. If that VLAN's router interface is not passive, the laptop can form an adjacency and advertise fake routes (even a better default route), pulling traffic through itself for interception or into a black hole.

Defender move

Passive interfaces everywhere users live; OSPF authentication between routers (MD5 or HMAC-SHA where your platform supports it); ACLs that drop OSPF (IP protocol 89) arriving from user ports; and watching the %OSPF-5-ADJCHG log messages, because an unexpected new neighbour is an incident.

Hinglish mein samjho

Cost = reference bandwidth / interface bandwidth, minimum 1. Default reference 100 Mb/s hai, toh 100M, 1G aur 10G sab cost 1. Har router pe auto-cost reference-bandwidth 10000 lagao. [110/20] matlab AD 110 aur total cost 20. Equal cost paths dono install hote hain. Attacker user VLAN pe OSPF bol ke fake routes inject kar sakta hai; passive interfaces aur authentication se roko.

    Packet Tracer limits and notes

    • You will not see 2WAY/DROTHER with only three routers. Add a fourth router to SW0 if you want to see two DROTHERs at 2-Way with each other.
    • show ip ospf interface brief is reported by a third party site as added in Packet Tracer 8.2. UNVERIFIED against Cisco release notes; use show ip ospf interface if it is missing.
    • ip ospf network point-to-point on Packet Tracer Ethernet interfaces is UNVERIFIED. If it is rejected, leave that link as broadcast: the two routers will elect a DR and BDR, and everything else still works.
    • The interface form ip ospf 1 area 0 is UNVERIFIED on every Packet Tracer image. The network statements above are the reliable way.
    • OSPF authentication in Packet Tracer is UNVERIFIED and outside this lesson's depth.
    • Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.

    Key takeaways

    • OSPF routers share one map per area and each runs SPF on it.
    • Area, subnet, timers and authentication must match; the process ID does not.
    • DR and BDR: highest priority then router ID, and the election is not preemptive.
    • Raise the reference bandwidth on every router so fast links get different costs.
    • Make user facing interfaces passive, and treat an unexpected new neighbour as an incident.
