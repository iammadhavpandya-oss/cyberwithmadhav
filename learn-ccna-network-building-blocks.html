3.1.01

Layers and encapsulation: how data gets wrapped

Lesson 1.4 introduced the layers. The CCNA expects you to use them as a tool: when something breaks, you work out which layer is failing and test that layer. Two models describe the same idea.

As data goes down the stack, each layer adds its own header: the application's data gets a TCP or UDP header (now a segment or datagram), then an IP header (a packet), then an Ethernet header and trailer (a frame), and finally the physical layer turns it into electrical, light or radio signals (bits). The receiver strips the headers in reverse. That is encapsulation and de-encapsulation.

  • A switch normally reads up to Layer 2 (MAC addresses in the frame).
  • A router reads up to Layer 3 (IP addresses in the packet), and rebuilds a new Layer 2 frame for every hop.
  • Firewalls read Layers 3 and 4 (addresses and ports), and next generation firewalls look into Layer 7 (which application, which URL).
Think of it like this

A letter goes in an envelope with the flat number (port), the envelope goes in a courier bag with the city address (IP), and the bag rides on whatever truck covers the next stretch of road (the frame). Each depot opens only the outer layer it needs and puts the bag on a new truck.

Defender move

Name the layer before you pick a control: ARP spoofing is a Layer 2 problem (fixed with Dynamic ARP Inspection, lesson 3.12), IP spoofing is Layer 3 (ACLs, lesson 3.9), session hijacking lives in the upper layers (fixed with TLS). The wrong layer means the wrong fix.

Hinglish mein samjho

Data neeche jaate hue har layer apna header lagati hai: segment (TCP), packet (IP), frame (Ethernet), phir bits. Receiver ulta khole. Switch Layer 2 (MAC), router Layer 3 (IP), firewall 3-4 aur NGFW Layer 7 tak dekhta hai. Problem kis layer pe hai, wahi decide karta hai fix kya hoga.

3.1.02

What each device does

Network device roles
DeviceWorks atJob
Layer 2 switchL2Forwards frames by MAC address inside one network (one VLAN). Learns which MAC lives on which port.
RouterL3Forwards packets by IP address between networks. Chooses the path using its routing table.
Layer 3 (multilayer) switchL2 and L3Switches and routes in hardware. Common as the core or distribution layer inside a campus.
Access point (AP)L1 and L2Bridges Wi-Fi clients onto the wired network.
Wireless LAN controller (WLC)managementConfigures and manages many lightweight APs centrally (lesson 3.13).
Firewall / NGFW and IPSL3 to L7Stateful filtering; next generation firewalls add application awareness and intrusion prevention, which blocks known attack patterns inline.
Endpoints and serversall layersLaptops, phones, cameras and printers; servers provide services like DNS, DHCP, web and file sharing.
PoE switchL1 and L2Power over Ethernet: powers phones, cameras and APs over the data cable.

You will also meet the classic designs. A two tier (collapsed core) campus has access switches connected to a pair of core and distribution switches. A three tier campus separates access, distribution and core. Data centres use spine and leaf, where every leaf switch connects to every spine, so any two servers are the same number of hops apart. A SOHO (small office, home office) network often has one box that is router, switch, AP and firewall at once, and the WAN connects sites to each other and to the cloud.

How attackers abuse this

Attackers love physical access. A live, unused wall port, or a cheap unmanaged switch someone put under a desk, lets a rogue laptop or a tiny implant join the internal network with no password at all.

Defender move

Shut unused switch ports and put them in an unused VLAN, lock wiring closets, label everything, and use port security or 802.1X so only known devices get access (lessons 3.4 and 3.12).

Hinglish mein samjho

Switch frames ko MAC se ek network ke andar bhejta hai, router packets ko IP se networks ke beech. L3 switch dono karta hai. AP Wi-Fi ko wired se jodta hai, WLC bahut saare APs manage karta hai, NGFW aur IPS application dekh ke attacks rokte hain. Khula unused port attacker ka entry point hai: band karo.

3.1.03

Cabling, duplex and the physical layer

Cable types
MediumTypical reachUse it for
Copper UTP (Cat5e, Cat6, Cat6A)Up to 100 m per run for common EthernetDesks, phones, APs, PoE devices
Multimode fibre (MMF)Hundreds of metres, depending on speed and fibre gradeInside a building, between floors and racks
Single-mode fibre (SMF)KilometresBetween buildings, campuses and service providers

Fibre does not make a single link magically faster; its advantages are distance and immunity to electrical noise. Old Ethernet needed crossover cables between similar devices, but modern ports use Auto-MDIX and work with either cable. In Packet Tracer you still pick the cable type, so the copper straight-through cable is the normal choice between a PC and a switch.

Half and full duplex

Hubs created one shared medium where only one device could talk at a time (half duplex), and collisions were normal. Switch ports are point to point, so both sides talk at once (full duplex) and you should see zero collisions. When one side is set to full and the other falls back to half, you get a duplex mismatch: the link works but is slow, the half duplex side counts collisions and late collisions, and the full duplex side counts CRC and input errors. The fix is to leave both ends on auto, or set both ends the same.

Think of it like this

Full duplex is a phone call: both talk and listen at once. Half duplex is a walkie talkie: one talks, the other waits. A mismatch is one person on a phone call and the other holding a walkie talkie, constantly cutting each other off.

Hinglish mein samjho

Copper UTP 100 m tak, multimode fibre building ke andar, single-mode kilometres tak. Fibre ka fayda distance aur noise se bachav hai. Switch ports full duplex hote hain, collisions zero hone chahiye. Duplex mismatch: ek side full, doosri half: link slow, late collisions aur CRC errors. Dono side auto ya same rakho.

3.1.04

TCP, UDP and the ports you must know

TCP is connection oriented. It sets up a session with a three way handshake, numbers every byte, acknowledges what arrived, resends what was lost and uses a window to control speed. UDP just sends: no handshake, no recovery, very little overhead. That makes UDP right for voice, video, DNS queries and anything where a late packet is useless anyway.

How attackers abuse this

An open Telnet port sends usernames and passwords in cleartext, so anyone who can capture traffic on the path can read them. And because a SYN gets a SYN-ACK from any open TCP port, scanners map every listening service on a network in minutes.

Defender move

Turn off what you do not need, replace cleartext protocols (Telnet, FTP, HTTP management) with SSH, SFTP and HTTPS, and filter management ports so only admin subnets reach them (lessons 3.3 and 3.9).

Hinglish mein samjho

TCP: handshake (SYN, SYN-ACK, ACK), sequence numbers, acknowledgement aur resend. UDP: bas bhej do, fast aur halka: voice, video, DNS. Ports yaad karo: SSH 22, Telnet 23 (cleartext, band karo), DNS 53, DHCP 67/68, TFTP 69, HTTPS 443, NTP 123, SNMP 161/162, syslog 514.

3.1.05

Reading interfaces like an engineer

Two commands answer most physical layer questions. show ip interface brief gives one line per interface with its IP and two status words: Status is Layer 1 (is there a working link?) and Protocol is Layer 2 (is the data link working?). show interfaces adds duplex, speed and the error counters.

Interface status
Status / ProtocolMeansCheck
up / upWorkingNothing to fix at L1 and L2
administratively down / downSomeone typed shutdownno shutdown
down / downNo physical linkCable, the other end, wrong port
up / downLink is there but L2 failsEncapsulation or keepalive mismatch, a problem at the far end

In the counters, CRC and input errors rising usually means a bad cable, interference or a duplex mismatch; late collisions on a switched link almost always mean a duplex mismatch. Practise reading them on R1 below. One of its interfaces has a problem.

    Hands-on lab

    Cisco Packet Tracer lab30 minutessimulated network

    Packet Tracer lab 3.1: build, cable and read interfaces

    You need: Cisco Packet Tracer (free with a Cisco Networking Academy account; version 9.0.1 was the current download on the NetAcad Resource Hub when this lesson was written). Devices: 1 x 2960-24TT switch, 1 x ISR4331 router, 2 x PC-PT, copper straight-through cables.

    Simulator lab, zero risk. This lab runs inside Cisco Packet Tracer, so it touches no real network. Packet Tracer is free with a Cisco Networking Academy account (netacad.com). It simulates a subset of Cisco IOS, so where support for a feature is uncertain we say so instead of promising it works.

    Topology and addressing

    DeviceInterfaceIPv4 address / prefixDefault gateway or note

    1. Place and cable

      Add the devices and cable them as in the diagram. Watch the link lights: switch ports often show orange for a short time before turning green, because they pass through spanning tree states first (lesson 3.5).

    2. Configure R1

      Router>enable
Router#configure terminal
Router(config)#hostname R1
R1(config)#interface GigabitEthernet0/0/0
R1(config-if)#ip address 192.168.10.1 255.255.255.0
R1(config-if)#no shutdown
R1(config-if)#end

    3. Address the PCs

      On each PC open Desktop, then IP Configuration, and enter the address, mask and gateway from the table.

    4. Test and watch the layers

      From PC1's Command Prompt run ping 192.168.10.1 and ping 192.168.10.12. Then switch to Simulation mode, filter for ICMP and ARP, and step through one ping. Open a PDU and match each part to a layer: Ethernet header (L2), IP header (L3), ICMP (the payload).

    5. Verify

      R1#show ip interface brief
R1#show interfaces GigabitEthernet0/0/0
SW1#show interfaces status

      On PC1: ipconfig and arp -a. The first ping may lose one reply while ARP finds R1's MAC address; that is normal.

    6. Force a mismatch and look

      SW1(config)#interface FastEthernet0/1
SW1(config-if)#duplex half
SW1(config-if)#speed 10
SW1(config-if)#end
SW1#show interfaces FastEthernet0/1

      Read the duplex and speed lines, then set the port back with duplex auto and speed auto.

    You are done when: R1 Gi0/0/0 is up/up with 192.168.10.1, both PCs ping R1 and each other, and you can point to the L2, L3 and ICMP parts of a PDU in Simulation mode.

    Packet Tracer limits and notes

    • Packet Tracer does not reliably produce realistic CRC errors or late collisions from a duplex mismatch, so treat step 6 as a where to look exercise, not proof of real error behaviour. UNVERIFIED how the counters react in your version.
    • Fibre cables exist in Packet Tracer, but the device needs a fibre capable port or module, and module names vary by model. UNVERIFIED per device.
    • Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.

    Key takeaways

    • Each layer adds a header; switches read L2, routers L3, NGFWs up to L7.
    • Copper to 100 m, multimode in buildings, single-mode for kilometres.
    • Switched links are full duplex with zero collisions; late collisions mean a duplex mismatch.
    • TCP is reliable and ordered, UDP is fast and light.
    • show ip interface brief first, show interfaces for the details.
