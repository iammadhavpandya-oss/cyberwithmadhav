CyberWithMadhav Learn: lesson 3.7 lab checklist
Packet Tracer lab 3.7: static, host and floating routes
https://www.cyberwithmadhav.com/learn-ccna-static-routing.html

Time: 50 minutes
You need: Cisco Packet Tracer (free with a Cisco Networking Academy account; version 9.0.1 was the current download on the NetAcad Resource Hub when this lesson was written). Devices: 3 x ISR4331, 2 x 2960, PC1, PC3, Server3. Enable ipv6 unicast-routing on every router.

ADDRESSING
  R1 | Gi0/0/0 | 192.168.1.1/24, 2001:db8:1:1::1/64 | LAN1
  R1 | Gi0/0/1 | 10.0.12.1/30, 2001:db8:12::1/64 | to R2
  R1 | Gi0/0/2 | 10.0.13.1/30, 2001:db8:13::1/64 | to R3
  R2 | Gi0/0/1 | 10.0.12.2/30, 2001:db8:12::2/64 | to R1
  R2 | Gi0/0/2 | 10.0.23.1/30, 2001:db8:23::2/64 | to R3
  R2 | Gi0/0/0 | 192.168.3.1/24, 2001:db8:1:3::1/64 | LAN3
  R3 | Gi0/0/1 | 10.0.13.2/30, 2001:db8:13::3/64 | to R1
  R3 | Gi0/0/0 | 10.0.23.2/30, 2001:db8:23::3/64 | to R2
  PC1 | Fa0 | 192.168.1.10/24 | gw 192.168.1.1
  PC3 | Fa0 | 192.168.3.10/24 | gw 192.168.3.1
  Server3 | Fa0 | 192.168.3.100/24 | gw 192.168.3.1

STEPS (tick each box when done)
[ ] 1. Address everything
      Note: Use the table. Check every router with show ip interface brief before adding a single route: half of all routing problems are an interface that is still shut.
[ ] 2. R1: primary, floating and host routes
      R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2
      R1(config)# ipv6 route 2001:db8:1:3::/64 2001:db8:12::2
      R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.13.2 5
      R1(config)# ipv6 route 2001:db8:1:3::/64 2001:db8:13::3 5
      R1(config)# ip route 192.168.3.100 255.255.255.255 10.0.13.2
[ ] 3. R2: default route back, plus a floating default
      R2(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.1
      R2(config)# ipv6 route ::/0 2001:db8:12::1
      R2(config)# ip route 0.0.0.0 0.0.0.0 10.0.23.2 5
[ ] 4. R3: routes to both LANs
      R3(config)# ip route 192.168.1.0 255.255.255.0 10.0.13.1
      R3(config)# ip route 192.168.3.0 255.255.255.0 10.0.23.1
      R3(config)# ipv6 route 2001:db8:1:1::/64 2001:db8:13::1
      R3(config)# ipv6 route 2001:db8:1:3::/64 2001:db8:23::2
[ ] 5. Compare paths
      Note: From PC1: tracert 192.168.3.10 should go R1, R2. tracert 192.168.3.100 should go R1, R3, R2, because the /32 host route wins over the /24.
[ ] 6. Fail the primary
      Note: Shut R1 Gi0/0/1 and run show ip route on R1: the floating route appears as [5/0] via 10.0.13.2. Ping PC3 again. Then bring Gi0/0/1 back.
[ ] 7. Verify
      R1# show ip route
      R1# show ip route static
      R1# show ip route 192.168.3.100
      R1# show ipv6 route static
      R1# show running-config | include ip route

DONE WHEN: R1 shows S 192.168.3.0/24 [1/0] via 10.0.12.2 and S 192.168.3.100/32 [1/0] via 10.0.13.2; the AD 5 route appears only while Gi0/0/1 is shut; tracert to the server goes through R3.

PACKET TRACER LIMITS AND NOTES
  - This lab corrects one detail you may see in other guides: on a /30 only .1 and .2 are usable, so R3 uses 10.0.13.2 and R2 uses 10.0.23.1.
  - As on real IOS, a static route via a next hop usually stays installed when the far router fails but your local interface stays up. That is why this lab shuts the local interface to test failover.
  - Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.
