3.7.01

Reading a routing table

R1#show ip route
Codes: L - local, C - connected, S - static, O - OSPF
       * - candidate default

Gateway of last resort is not set

C        10.0.12.0/30 is directly connected, GigabitEthernet0/0/1
L        10.0.12.1/32 is directly connected, GigabitEthernet0/0/1
S        192.168.3.0/24 [1/0] via 10.0.12.2
O        10.20.0.0/16 [110/20] via 10.0.12.2, 00:01:12, GigabitEthernet0/0/1
  • Code: C connected, L local (the router's own address as a /32), S static, O OSPF, and an asterisk marks a candidate default route.
  • Prefix and length: the destination network.
  • [AD/metric]: administrative distance (how much the router trusts the source) and the protocol's metric (how far).
  • via: the next hop, then for dynamic routes the age and the exit interface.
  • Gateway of last resort: the default route, used when nothing more specific matches.
Hinglish mein samjho

Routing table mein code (C connected, L local, S static, O OSPF, * default), prefix, [AD/metric], next hop aur exit interface hota hai. Gateway of last resort matlab default route.

3.7.02

How a router picks a route

  1. Longest prefix match first. Of all routes that contain the destination, the most specific wins. A /32 beats a /24, which beats a /16, which beats the /0 default. This happens no matter what the AD is.
  2. AD only for identical prefixes. When two sources offer the same prefix and length, only the lowest AD enters the table.
  3. Metric breaks ties within one routing protocol.

3.7.03

Static routes: network, default, host and floating

! network route via a next hop (recursive: the router then looks up how to reach 10.0.12.2)
R1(config)#ip route 192.168.3.0 255.255.255.0 10.0.12.2
! exit interface only: fine on point to point links, avoid on Ethernet
R1(config)#ip route 192.168.3.0 255.255.255.0 GigabitEthernet0/0/1
! fully specified: both
R1(config)#ip route 192.168.3.0 255.255.255.0 GigabitEthernet0/0/1 10.0.12.2
! default route
R2(config)#ip route 0.0.0.0 0.0.0.0 10.0.12.1
! host route
R1(config)#ip route 192.168.3.100 255.255.255.255 10.0.13.2
! floating static: AD 5, only used if the AD 1 route disappears
R1(config)#ip route 192.168.3.0 255.255.255.0 10.0.13.2 5
! IPv6 equivalents
R1(config)#ipv6 route 2001:db8:1:3::/64 2001:db8:12::2
R1(config)#ipv6 route ::/0 2001:db8:12::2
  • A floating static sits in the running config but stays out of the routing table while the primary route is installed.
  • A static route via a next hop stays installed as long as the router can still reach that next hop through an up interface. If the far router dies but your local interface stays up, the route usually stays too, and traffic is black holed. That is why real networks pair statics with tracking or use a routing protocol.
  • For IPv6, if the next hop is a link-local address (fe80::), you must also name the exit interface.
Hinglish mein samjho

Static route next hop IP se (recursive lookup), exit interface se (sirf point to point pe) ya dono se. Default 0.0.0.0/0, host route /32, floating static higher AD ke saath (jaise 5), jo primary girne pe hi table mein aata hai. Local interface up rahe aur door ka router mar jaaye toh route rehta hai aur traffic black hole hota hai.

3.7.04

Troubleshooting: it is always the way back

A ping needs a route there and a route back. Most static routing tickets are a forgotten return route on the far router. Work hop by hop: show ip route on each router for the destination and for the source, then traceroute (on a PC: tracert) to see where packets stop.

R1#show ip route 192.168.3.100
Routing entry for 192.168.3.100/32
  Known via "static", distance 1, metric 0
  Routing Descriptor Blocks:
  * 10.0.13.2
      Route metric is 0, traffic share count is 1
How attackers abuse this

Routers are not usually attacked through static routes over the wire, but a compromised admin account can add one quietly: send a subnet's traffic through a capture box, or black hole a monitoring server so alerts never arrive. Asymmetric paths also break stateful firewalls, which see only half of each session and drop it.

Defender move

Strong AAA and MFA for device logins (lesson 3.12), configuration change logging to syslog (lesson 3.11), regular config backups you can diff, and a review of show ip route after every change. Null routes are a defensive tool too: ip route 198.51.100.0 255.255.255.0 Null0 silently drops traffic to a known bad prefix.

Hinglish mein samjho

Ping ko jaane aur wapas aane dono ka route chahiye. Zyada tar problem far router pe return route bhoolna hota hai. Har hop pe show ip route aur traceroute. Compromised admin chupke se route daal ke traffic capture ya monitoring black hole kar sakta hai: AAA, MFA, change logging aur config backups se bachav. Null0 route bad prefix ko drop karta hai.

    Hands-on lab

    Cisco Packet Tracer lab50 minutessimulated network

    Packet Tracer lab 3.7: static, host and floating routes

    You need: Cisco Packet Tracer (free with a Cisco Networking Academy account; version 9.0.1 was the current download on the NetAcad Resource Hub when this lesson was written). Devices: 3 x ISR4331, 2 x 2960, PC1, PC3, Server3. Enable ipv6 unicast-routing on every router.

    Simulator lab, zero risk. This lab runs inside Cisco Packet Tracer, so it touches no real network. Packet Tracer is free with a Cisco Networking Academy account (netacad.com). It simulates a subset of Cisco IOS, so where support for a feature is uncertain we say so instead of promising it works.

    1. Address everything

      Use the table. Check every router with show ip interface brief before adding a single route: half of all routing problems are an interface that is still shut.

    2. R1: primary, floating and host routes

      R1(config)#ip route 192.168.3.0 255.255.255.0 10.0.12.2
R1(config)#ipv6 route 2001:db8:1:3::/64 2001:db8:12::2
R1(config)#ip route 192.168.3.0 255.255.255.0 10.0.13.2 5
R1(config)#ipv6 route 2001:db8:1:3::/64 2001:db8:13::3 5
R1(config)#ip route 192.168.3.100 255.255.255.255 10.0.13.2

    3. R2: default route back, plus a floating default

      R2(config)#ip route 0.0.0.0 0.0.0.0 10.0.12.1
R2(config)#ipv6 route ::/0 2001:db8:12::1
R2(config)#ip route 0.0.0.0 0.0.0.0 10.0.23.2 5

    4. R3: routes to both LANs

      R3(config)#ip route 192.168.1.0 255.255.255.0 10.0.13.1
R3(config)#ip route 192.168.3.0 255.255.255.0 10.0.23.1
R3(config)#ipv6 route 2001:db8:1:1::/64 2001:db8:13::1
R3(config)#ipv6 route 2001:db8:1:3::/64 2001:db8:23::2

    5. Compare paths

      From PC1: tracert 192.168.3.10 should go R1, R2. tracert 192.168.3.100 should go R1, R3, R2, because the /32 host route wins over the /24.

    6. Fail the primary

      Shut R1 Gi0/0/1 and run show ip route on R1: the floating route appears as [5/0] via 10.0.13.2. Ping PC3 again. Then bring Gi0/0/1 back.

    7. Verify

      R1#show ip route
R1#show ip route static
R1#show ip route 192.168.3.100
R1#show ipv6 route static
R1#show running-config | include ip route

    You are done when: R1 shows S 192.168.3.0/24 [1/0] via 10.0.12.2 and S 192.168.3.100/32 [1/0] via 10.0.13.2; the AD 5 route appears only while Gi0/0/1 is shut; tracert to the server goes through R3.

    Packet Tracer limits and notes

    • This lab corrects one detail you may see in other guides: on a /30 only .1 and .2 are usable, so R3 uses 10.0.13.2 and R2 uses 10.0.23.1.
    • As on real IOS, a static route via a next hop usually stays installed when the far router fails but your local interface stays up. That is why this lab shuts the local interface to test failover.
    • Packet Tracer simulates a subset of IOS. If a command here is rejected in your version, note it, skip that step and carry on; the concept still applies to real Cisco gear.

    Key takeaways

    • Longest prefix first, then AD, then metric.
    • Static routes: network, default, host, floating.
    • Floating statics wait in the config until the primary disappears.
    • Every path needs a return path.
    • Log and review route changes like any security relevant change.
